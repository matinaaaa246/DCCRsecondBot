راهنمای اجرا
=============

ساختار پوشه:
- M.py                     -> اسکریپت اصلی بات تلگرام (قبلاً multi_project_bot.py بود)
- requirements.txt        -> وابستگی‌های لازم (requests, ccxt, pandas)
- symbol_projects/        -> پوشه هر ۷ پروژه پایتون (BNB, BTC, DOGE, ETH, SOL, XAUT, XRP)
                              هر پروژه در زیرپوشه خودش. اسکریپت هر پروژه فقط داده خام
                              (کندل + FVG) تولید می‌کنه؛ هیچ پرامپتی داخلش نیست.

نحوه کار (دو مرحله‌ای):
هر ۱۰ دقیقه یک‌بار (نه به‌صورت چرخه‌ای/پشت‌سرهم)، بات هر ۷ اسکریپت رو هم‌زمان
(هرکدوم در ترد جداگانه‌ی خودش) اجرا می‌کنه (هر کدوم داخل پوشه خودش، چون خروجی
JSON با مسیر نسبی نوشته می‌شه). هر اسکریپت یک‌بار ۲۰۰ کندل آخر (تایم‌فریم ۵ دقیقه)
رو می‌گیره و در یک فایل واحد "<NAME>-MarketData.json" ذخیره می‌کنه؛ این فایل شامل
دو بخشه:
  1) کل ۲۰۰ کندل (برای مرحله ۱)
  2) لیست FVGهای شناسایی‌شده فقط روی ۱۰۰ کندل آخر (برای مرحله ۲)

برای هر پروژه، درست قبل از اجرای اسکریپت، فایل JSON قبلی (اگه از اجرای قبل مونده
باشه) حذف می‌شه؛ بعد اسکریپت اجرا و فایل تازه ساخته می‌شه؛ اگه اسکریپت به هر دلیلی
این فایل رو نسازه، خطا در نظر گرفته می‌شه (هیچ‌وقت نسخه قدیمی/باقی‌مونده به‌جای
محتوای تازه خونده و به هوش مصنوعی داده نمی‌شه).

بلافاصله بعد از خوندن فایل تازه، دو تماس جدا با هوش مصنوعی گرفته می‌شه (پرامپت هر
دو مرحله ثابت و مشترک بین هر ۷ پروژه‌ست، داخل M.py با نام‌های PROMPT_STAGE_1 و
PROMPT_STAGE_2):
  • مرحله ۱ (تحلیل): PROMPT_STAGE_1 + ۲۰۰ کندل آخر -> یک گزارش تحلیلی خام SMC/RTM
    (بدون سیگنال). این جواب فقط به‌عنوان ورودی مرحله ۲ استفاده می‌شه و خودش هیچ‌وقت
    به تلگرام فرستاده نمی‌شه (فقط اگه SAVE_STAGE1_DEBUG_FILE روشن باشه، برای دیباگ
    توی فایل "<NAME>-Stage1-LastAnalysis.txt" کنار همون پروژه ذخیره می‌شه).
  • مرحله ۲ (بررسی نهایی و تریگر): PROMPT_STAGE_2 + خروجی مرحله ۱ + لیست FVGهای
    ۱۰۰ کندل آخر -> سیگنال نهایی (یا HOLD). فقط همین خروجیه که فیلتر وین‌ریت روش
    اعمال و در صورت قبول شدن به همه چت‌هایی که با بات تعامل داشتن (پیوی یا گروه)
    ارسال می‌شه.

بعد از تمام‌شدن هم‌زمانِ هر ۷ پروژه (که یعنی ۱۴ تماس با هوش مصنوعی، دو تا برای هر
پروژه، ولی خود ۷ پروژه با هم و موازی اجرا می‌شن نه پشت‌سرهم)، بات صبر می‌کنه تا از
شروع همون دور دقیقاً ۱۰ دقیقه (CYCLE_INTERVAL_SECONDS در M.py) گذشته باشه و بعد دور
بعدی رو شروع می‌کنه. اگه یک دور بیشتر از ۱۰ دقیقه طول بکشه، دور بعدی بدون تاخیر
اضافه بلافاصله شروع می‌شه (تا زمان‌بندی عقب نیفته).

هم اجرای هر اسکریپت پایتون و هم هر درخواست به API هوش مصنوعی (هر دو مرحله)، بدون
هیچ محدودیت زمانی (timeout) هستن؛ یعنی هر چقدر طول بکشن، بات صبر می‌کنه و هیچ‌وقت
به‌خاطر timeout قطع نمی‌شه.

نصب و اجرا:
1) pip install -r requirements.txt --break-system-packages
2) این Environment Variable ها رو روی Render (یا هر جا دیپلوی می‌کنید) ست کنید:
     TELEGRAM_BOT_TOKEN = توکن بات تلگرام شما (از BotFather)
     AI_API_KEY = کلید API شما
     AI_MODEL   = نام مدل (مثلاً qwen3.8-flash)
   اگه ست‌شون نکنید، مقدار پیش‌فرضی که داخل M.py نوشته شده استفاده می‌شه، ولی
   بهتره برای امنیت از Environment Variable استفاده کنید نه مقدار هاردکد.
3) python3 M.py

نکات مهم:
- هوش مصنوعی این پروژه با کتابخونه رسمی openai (پکیج pip: openai) صدا زده
  می‌شه (تابع ask_ai داخل M.py) — فقط با AI_API_KEY و AI_MODEL، بدون نیاز به
  آدرس/URL جداگانه؛ این دو مقدار اول از Environment Variable خونده می‌شن،
  اگه ست نشده باشن از مقدار پیش‌فرض داخل خود M.py استفاده می‌شه. هیچ محدودیت
  زمانی (timeout) روی این تماس اعمال نمی‌شه.
- Privacy Mode بات رو در BotFather با دستور /setprivacy روی Disable بذارید تا
  پیام‌های عادی گروه (نه فقط کامندها) رو ببینه.
- برای افزودن پروژه هشتم یا پروژه‌های بیشتر در آینده، کافیه یک پوشه جدید داخل
  symbol_projects بسازید و فایل .py مربوطه رو داخلش بذارید؛ بات به‌صورت خودکار
  همه زیرپوشه‌ها رو در ابتدای اجرا شناسایی می‌کنه (نیازی به تغییر کد نیست).
- اگه یک پروژه دقیقاً اسم فایل خروجی JSON متفاوتی داره (نه "<PROJECT>-MarketData.json")،
  باید در discover_projects داخل M.py دستی تنظیم بشه.
- روی سرورهای لینوکسی (مثل Render) ممکنه دستور "python" وجود نداشته باشه و فقط
  "python3" نصب باشه. اگه با خطای "python: command not found" مواجه شدید، مقدار
  PYTHON_EXECUTABLE داخل M.py رو از "python" به "python3" تغییر بدید.

دیپلوی روی Render.com (Web Service):
==========================================
۱) یک ریپازیتوری گیت با همین فایل‌ها بسازید (M.py, requirements.txt,
   symbol_projects/, render.yaml) و به گیت‌هاب پوش کنید.
۲) در Render: New -> Web Service -> ریپازیتوری رو انتخاب کنید. اگه فایل
   render.yaml رو دیده باشه (Blueprint)، Build/Start Command و healthCheckPath
   خودکار پر می‌شن؛ در غیر این صورت دستی ست کنید:
     Build Command: pip install -r requirements.txt
     Start Command: python3 M.py
     Health Check Path: /health
۳) Environment Variables رو در تنظیمات سرویس ست کنید:
     TELEGRAM_BOT_TOKEN, AI_API_KEY, AI_MODEL
   (PING_INTERVAL_SECONDS اختیاریه، پیش‌فرض ۳۰۰ ثانیه/۵ دقیقه‌ست.)
   نیازی نیست RENDER_EXTERNAL_URL رو دستی ست کنید؛ Render خودش این رو با
   آدرس عمومی سرویس‌تون پر می‌کنه.
۴) بعد از دیپلوی، بات هم روی مسیر "/" (متن ساده "Bot is running.") و هم روی
   "/health" (JSON با وضعیت واقعی آخرین دور تحلیل) جواب می‌ده.

جلوگیری از خوابیدن سرویس + مانیتورینگ هر ۵ دقیقه:
==========================================
پلن رایگان Render بعد از ۱۵ دقیقه بدون ترافیک HTTP واقعی از بیرون، سرویس رو
می‌خوابونه (spin down). برای این پروژه دو لایه حفاظت گذاشته شده:

۱) خودپینگ داخلی (از قبل توی کد فعاله، کار اضافه‌ای لازم نیست):
   یک ترد پس‌زمینه (keep_alive_ping در M.py) هر PING_INTERVAL_SECONDS (پیش‌فرض
   ۵ دقیقه) به آدرس عمومی خود سرویس (RENDER_EXTERNAL_URL، که Render خودکار
   ست می‌کنه) درخواست GET می‌فرسته. این ترافیک از دید Render واقعی حساب
   می‌شه و جلوی خواب رفتن رو می‌گیره.

۲) مانیتورینگ بیرونی (پیشنهادی، برای اطمینان مضاعف — چون اگه کل پروسه کرش
   کنه، خودپینگ داخلی هم دیگه اجرا نمی‌شه):
   یک سرویس رایگان مثل UptimeRobot یا cron-job.org رو هر ۵ دقیقه به آدرس
   زیر ست کنید:
     https://<آدرس-سرویس-شما>.onrender.com/health
   این مسیر یک JSON با فیلدهای last_cycle_started_at، last_cycle_finished_at
   و stale برمی‌گردونه. اگه بیشتر از حدود ۲۲ دقیقه (۲ برابر فاصله ۱۰ دقیقه‌ای
   + حاشیه) هیچ دوری کامل نشده باشه، stale=true می‌شه و HTTP status هم 503
   برمی‌گرده — یعنی سرویس مانیتورینگ می‌تونه بفهمه بات واقعاً هنگ/کرش کرده،
   نه فقط اینکه وب‌سرور جواب می‌ده. اکثر این سرویس‌ها امکان اطلاع‌رسانی
   (ایمیل/تلگرام/SMS) در صورت قطعی رو هم دارن.
